## 分阶段证据

1. **最小加载通过**：在官方 app.html 追加一个带固定 ID 的验证标记，真实客户端窗口中可见；随后移除并读取确认。见 `minimal-load.json`、`minimal-rollback.json`。
2. **完整退出回滚通过**：退出官方应用后 49363 端口关闭；主程序与 `resources.pack` SHA-256 未变；`codesign --verify --deep --strict` 在沙盒外返回 0。见 `minimal-restart-rollback.json`。沙盒内签名工具一度误报 invalid signature，已在相同应用的完整系统环境中复核通过，不能把误报当作原应用被改动。
3. **本机限定通过**：`lsof` 实测监听 `127.0.0.1:49363`，主进程位于官方安装路径。未采用 dylib 注入、资源解包重写、重新签名或系统安全设置修改。
4. **内部视觉通过**：真实窗口显示方形封面、封面衍生的动态模糊背景、当前歌词高亮/相邻歌词柔化；保留原生歌词滚动、翻译、错误刷新、返回及播放控件。长标题最多两行。
5. **即时切换通过**：⌘⇧A 恢复原生唱片/背景；点击 AURORA 再次启用。原生歌词加载失败在关闭样式后仍可见，见 `native-toggle-off.png`。
6. **重复加载通过**：连续加载两次后只有一个样式、背景、开关；原生封面节点对象未替换。见 `lifecycle-and-frame-sample.json`。
7. **完整卸载通过**：关闭脚本后全局插件对象不存在、样式数量 0、背景/开关/标记数量 0。监听器与 Observer 由 destroy 方法同步清理。见 `full-plugin-unload.json`。
8. **冷启动通过**：⌘Q 后运行交付启动器；首页未受影响；稍后点击歌曲封面进入播放页，适配器自动出现并正确加载封面。
9. **原生控件实测**：下一首/上一首改变标题、封面和背景；播放与暂停图标切换；歌词 current 状态由原生程序更新。未修改播放事件、音频解码和网络请求。原应用闲置时会自动收起头尾控件，点击页面会重新显示。
10. **结束状态**：恢复 Life Will Change，通过官方 Controls 菜单执行 Pause 后再次检查显示 Play，确认暂停；保留 Aurora 开启。原生进度条点击可跳转，暂停时歌词可能到下一次播放才更新。最终截图见 `aurora-final.png`；最终文件完整性和内部状态见 `final-integrity.json`、`final-runtime.json`。

## 性能与边界

- 120 帧短时前台 rAF 采样：中位与 P95 约 16.67ms，最慢一帧约 117ms。可见短暂卡顿，不能据此宣称无卡顿或持续稳定 60fps。
- 背景使用 CSS 合成动画；没有自建歌词定时器、Canvas/WebGL 渲染器或 JavaScript 逐帧绘制。支持 `prefers-reduced-motion`。
- 尚未做长期 GPU/功耗、后台电量、所有窗口大小或 macOS 版本矩阵测试；不验证音质。
- 测试过程中部分歌曲曾出现原生歌词加载失败，也出现切歌后短暂保留旧封面/歌词的加载过程；关闭插件仍能观察到原生错误，冷启动后歌词恢复。插件不伪造歌词，也不负责修复上游请求。
- 当前为手动启动的会话插件，**没有自动开机/普通图标启动常驻安装**。每次彻底退出后需运行启动脚本重新加载。页面完整刷新也需重新运行启动脚本。
- 关闭样式或卸载插件后，调试端口仍属于本次官方客户端进程；**必须 ⌘Q 才关闭端口**。普通启动则不会开启端口。
- 只适配已核验的 3.1.13 (3451)；版本更新时停止加载并重新检查。

## v0.2 歌词扩展与动态 · 同日后续

- 定位到右侧原生容器仍保留 80px 底部 padding，加上插件布局预留空间与宽幅歌词渐隐，导致歌词区只有 233.93px。移除重复留白并收紧间距后，同一窗口歌词区达到 431.93px。
- 原窗口显示约 3 组歌词；现测可同时显示 7 组原文/译文（长句换行时数量会变）。保留窄边缘渐隐，后续歌词延伸到播放条上方。
- 按原生 `.current` 切换触发 Web Animations：相邻行依次滑动、轻微越过后回弹；当前行渐亮并放大，远近歌词渐变柔化。保留原生滚动与歌词时间，不引入假逐字进度。
- 实际播放验收统计记录了 19 次当前行切换；每次只对视窗附近的行添加动画。`lyrics-motion-runtime.json` 为录制后的统计快照；`lyrics-motion-v0.2.mp4` 为约 6.9 秒、160 帧实际客户端截图按捕获时间合成的无声预览。该预览采样率约 23fps，不作为实际渲染帧率证明。
- `lyrics-expanded.json` 保存区域高度与可见行边界；`lyrics-v0.2-unload.json` 记录卸载后插件对象不存在、样式/自定义歌词属性/动画残留均为 0。
- 当前页面模拟 `prefers-reduced-motion: reduce` 后，背景动画为 none、歌词 CSS 过渡时长为 0s，脚本动画停止；测试后恢复页面原媒体设置。
- 最终保留 v0.2 开启，并通过官方 Controls 菜单暂停，确认菜单恢复显示 Play。

## v0.3 真实逐词高亮与统一滚动 · 后续修订

- v0.2 仅订阅行级 current 类，并在原生滚动上额外叠加位移，未实现用户所需的跟唱高亮。本轮已移除该叠加位移。
- 实际检查官方音乐状态的 `async:lyric.yrcInfo`，发现当前歌曲已经缓存 YRC：38 行、219 个有绝对毫秒时间的词段，同时有按 YRC 时间对齐的翻译。此前“未接入逐词时间”的实现限制不代表客户端没有逐词数据。
- 集成固定版本 AMLL DOM 0.6.0，原生音频/队列仍由网易云控制。只在官方内部歌词区域渲染歌词。原生歌词节点保留，启用时隐藏，卸载时恢复。
- 订阅原生模块 131 的未取整音乐进度流；模块 111 的播放条时钟是整秒值，未用于逐词同步。根据原生精确采样在帧间平滑推进；暂停、倍速、原生拖动进度和跳转分别处理。
- CEF 116 不支持无前缀 `mask-image`，AMLL 实际使用 WebKit CSS calc 遮罩，更新 `--amll-player-time`。不能把 Web Animations 数量为 0 当作没有逐词高亮。暂停实测 9 个当前词遮罩值及 CSS 时间在约 1.2 秒内均未变化。
- 真实播放录制 `word-highlight-v0.3.mp4` 约 9.5 秒、200 张实际客户端画面，能观察当前句内部先后点亮和连续切行。录屏为无声采样预览，不能作为音质、听感同步或完整帧率证明。
- 180 帧前台时钟采样：显示时间单调，和最近原生精确进度样本的最大差为 47ms。该差包含两次原生进度采样之间正常的帧间推进，不是与扬声器音频的实测延迟。
- 360 帧的同一歌词元素追踪中，发生约 50.9 CSS px 的滚动，35 帧有明显位移，单帧最大约 4 CSS px；此样本没有整行跳位。当前 600 帧窗口的中位/P95 帧间隔约 16.67ms，未做长期功耗或所有歌曲测试。
- 新增 8 个时间解析与时钟测试，全部通过：绝对词时间、零时长标点、元数据忽略、翻译对齐、纯 LRC 回退、暂停、倍速/跳转和失去进度心跳上限。
- 修复开关关闭导致容器零尺寸、重新开启错位的问题：关闭时释放歌词实例，开启时在可见容器重建；歌词加载中的暂时隐藏保留布局尺寸。离开播放页也释放实例，重新进入再创建。
- 快捷键关闭会恢复原生歌词与 aria 属性；完整卸载后自定义 host/player、隐藏原生属性和样式数量均为 0。订阅和帧循环由 destroy 清理。见 `word-full-unload.json`。
- 冷启动测试发现原生模块尚未准备好时的错误会被启动器误报为失败，已改为明确的 loading/ready 状态并等待；复测启动成功，随后打开播放页可加载逐词歌词。见 `word-cold-start.json`。
- 引擎与 CSS 已本地打包，运行时不从第三方服务器请求脚本或歌词。上游许可证和来源在 `plugin/vendor/`。
- 仅有行级 LRC 的歌曲回退为行级显示；没有词时间时不按字符数伪造跟唱进度。当前实际播放验收针对上述 YRC 歌曲。
